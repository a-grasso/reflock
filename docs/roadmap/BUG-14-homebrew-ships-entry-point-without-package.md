# BUG-14 - the Homebrew formula ships the entry point without the package

Source: the public-presentable pass, 2026-08-09 (install audit).
Status: fixed in `.github/workflows/release.yml`; the published tap formula is
corrected by the next release.

## The bug

`brew install a-grasso/tap/reflock` installs a command that cannot start:

```
$ reflock --version
ModuleNotFoundError: No module named 'reflock_lib'
```

The formula's install block was:

```ruby
bin.install "reflock.py" => "reflock"
```

which was correct while reflock was literally one file, and became wrong the
moment the implementation moved into the `reflock_lib` package beside it. The
source tarball contains the package; the formula simply never installed it.

## Why nothing caught it

Three separate safety nets each missed it for the same reason - they all run
from the repo root, where `reflock_lib` is importable no matter how the entry
point was installed:

- `just gate` runs `python3 reflock.py check` in the checkout.
- The release workflow verifies the *version*, never that the artifact runs.
- The formula's `test do` block asserted only on `--help`, and it appears never
  to have run against a bottle.

`install.sh` was unaffected: it symlinks the entry point in place, and Python
resolves a symlink before putting the script's directory on `sys.path`, so the
package is always found next to the real file. That the *supported* path kept
working is exactly why the unsupported one could stay broken for a release
cycle.

## The fix

Formula (generated by `release.yml`): both the entry point and the package go
into `libexec`, with a symlink into `bin` - the same symlink property
`install.sh` already depends on.

```ruby
libexec.install "reflock.py", "reflock_lib"
rewrite_shebang detected_python_shebang, libexec/"reflock.py"
bin.install_symlink libexec/"reflock.py" => "reflock"
```

The formula's test block now runs a real `stamp` then `check` round trip rather
than `--help`.

## The regression test

A formula test only runs at release time, in another repo, and this bug proves
that is too late. `ci.yml` grows an `install-layouts` job that rebuilds both
distribution layouts - the `install.sh` symlink and the Homebrew
`libexec` + `bin` symlink - and drives `--version`, `stamp` and `check` from a
directory outside the checkout, on every push and pull request.

The general lesson, worth applying to any future packaging: **verify the
artifact from where a user runs it, never from the tree that built it.**
